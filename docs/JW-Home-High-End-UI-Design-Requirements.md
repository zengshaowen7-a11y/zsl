# JW Dropshipping Home 高端视觉设计需求文档

## 1. 文档信息

- **项目名称**：JW Dropshipping 官网 Home 页面视觉升级
- **使用对象**：品牌 UI 设计师、网页视觉设计师、交互动效设计师、前端开发工程师
- **参考页面**：https://zsl111.netlify.app/#quote
- **设计范围**：仅对现有 Home 页面进行视觉、版式、素材、动效和转化体验升级
- **设计目标**：在不改变信息架构和业务逻辑的前提下，使页面呈现成熟、可信、专业、国际化的中国供应链服务商品牌形象

## 2. 项目目标

本次升级不是重新策划网站，也不是改写业务内容，而是通过更高质量的视觉设计，让现有内容获得更强的品牌表达和转化能力。

页面应同时传达以下感受：

1. **专业可靠**：真实团队、真实仓库、真实流程，避免泛化的跨境电商模板感。
2. **清晰克制**：信息层级明确，不依赖大量装饰、玻璃效果或复杂渐变制造“高级感”。
3. **运营导向**：突出采购、质检、仓储、包装和发货的实际工作，而非空泛营销口号。
4. **国际化**：面向英语市场，视觉密度、排版和素材质量应符合成熟 B2B 服务网站标准。
5. **转化友好**：用户始终知道 JW 提供什么、合作是否复杂、为什么可信，以及下一步如何获取报价。

## 3. 不可变更边界

以下内容必须保持不变：

- 页面现有信息架构
- 模块顺序
- 英文文案内容
- 服务项目与业务逻辑
- CTA 目标和表单字段
- 主品牌色：`#167449`
- 深色背景：`#0B2920`
- 强调绿色：`#42B978`
- 现有页面的核心链接关系

允许设计师调整：

- 栅格、留白、比例和视觉层级
- 字体字号、字重和行高
- 图片裁切、图片组合与素材选择
- 图标风格
- 分隔线、背景层次和模块衔接
- Hover、滚动、展开、表单反馈等交互
- 在不影响信息架构的情况下补充真实仓库图片、团队照片、流程视频和局部运营细节

禁止使用：

- 大面积绿色渐变作为主要视觉语言
- 玻璃拟态、发光光晕、装饰性漂浮圆球
- 多层卡片嵌套
- 与真实供应链业务无关的抽象 3D 插画
- 过量自动轮播和影响阅读的入场动画
- 缺少业务内容的纯装饰大图
- 过度圆角，卡片圆角建议不超过 `8px`

## 4. 整体视觉方向

### 4.1 品牌关键词

`Reliable`、`Operational`、`Human-led`、`Precise`、`Global`、`Premium but practical`

### 4.2 色彩系统

| 用途 | 色值 | 使用建议 |
| --- | --- | --- |
| 主品牌绿 | `#167449` | 主 CTA、链接、选中状态、关键数据 |
| 深绿色 | `#0B2920` | Hero、重点证明区、最终转化区 |
| 强调绿色 | `#42B978` | 深色背景上的 CTA、图标、状态提示 |
| 页面背景 | `#FFFFFF` | 主内容区 |
| 浅色区块 | `#F3F7F4` | 流程、对比、FAQ 等辅助区块 |
| 正文 | `#27332E` | 正文与主要信息 |
| 辅助文字 | `#67746E` | 描述、标签、次要说明 |
| 分隔线 | `#D8E2DC` 附近 | 表格、列表、区块边界 |

配色原则：

- 深绿色只用于需要建立信任或推动转化的重点区域。
- 强调绿色面积应小于主背景色，避免整页发亮。
- 白色与浅灰绿色应承担主要阅读空间。
- 避免用多个相近绿色填满所有组件，应依靠黑白灰、图片和留白建立层次。

### 4.3 字体与排版

- 使用现代无衬线字体，建议方向：Inter、Manrope、Plus Jakarta Sans 或同等气质字体。
- H1 桌面端建议 `56–64px`，移动端 `38–44px`。
- H2 桌面端建议 `40–50px`，移动端 `32–38px`。
- H3 建议 `20–26px`，根据容器密度调整。
- 正文建议 `16–18px`，行高 `1.6–1.75`。
- 标签和 Eyebrow 建议 `11–13px`，使用全大写和高字重，不使用负字距。
- 正文最大宽度约 `620px`，避免横跨整屏。
- 标题换行应经过人工控制，避免桌面端出现孤立单词。

### 4.4 栅格与留白

- 桌面端内容最大宽度建议 `1180–1240px`。
- 主栅格使用 12 列体系。
- 常规模块上下间距建议 `96–128px`。
- 模块内部标题与内容间距建议 `40–56px`。
- 移动端页面左右安全边距 `16–20px`。
- 不使用浮动大卡片模拟页面区块，模块应表现为完整的全宽内容带。

### 4.5 图标系统

- 使用统一线性图标，建议 Lucide 风格。
- 图标线宽、尺寸和颜色保持一致。
- 工具和状态优先使用用户熟悉的符号。
- 图标用于辅助扫描，不替代关键文字。

## 5. 图片与视频素材方向

### 5.1 素材原则

所有主要图片必须与真实业务相关，优先级如下：

1. JW 自有团队和仓库实拍
2. JW 实际质检、扫码、包装、贴标和发货过程
3. 能够明确展示工作内容的高质量补充素材
4. 必要时生成符合真实仓库环境的定制图片

避免：

- 握手、开会、看屏幕等泛商务图库
- 无法判断业务场景的仓库远景
- 过暗、过度调色或背景虚化严重的素材
- 人物姿势和设备使用方式不符合实际流程的 AI 图片

### 5.2 建议素材清单

- 仓库收货与扫码：横版 `2400 × 1600px` 以上
- 质检人员检查产品：横版及竖版各一组
- 数量、条码、标签、包装细节：近景至少 6 张
- 品牌包装与装箱：横版至少 3 张
- 拣货、分拣与发货：横版至少 3 张
- 客户经理或运营人员：自然工作状态照片至少 3 张
- 仓库完整流程视频：30–60 秒
- QC 操作短视频：10–20 秒
- 打包及分拣短视频：10–20 秒

图片需提供 WebP/AVIF 输出版本，并保留原始高清文件。

## 6. 页面模块设计需求

### 6.1 Header 导航

**保留内容**：Logo、Services、How It Works、Why JW、Testimonials、Contact、语言选择、Get a Free Quote。

**版式建议**：

- 桌面端使用单行水平导航，Header 高度约 `76–84px`。
- Logo 保持清晰可见，不应缩小为普通图标。
- 主导航位于中部，语言和报价按钮位于右侧。
- 当前页面使用细线或文字颜色变化表示，不使用大型胶囊背景。
- `Get a Free Quote` 使用 `#167449`，保持全站最明确的导航 CTA。
- Services 下拉菜单采用白色背景、细边框和清晰分组，避免过大面积遮挡 Hero。

**交互建议**：

- Header 可在向下滚动后轻微收紧高度并保持吸顶。
- 下拉菜单使用 `160–220ms` 淡入和位移动效。
- 键盘操作应支持 Tab、Enter、Esc。
- 移动端使用菜单图标，展开后显示完整导航和独立 CTA。

### 6.2 Hero 首屏

**保留内容**：现有 Eyebrow、H1、说明文案、两个 CTA、三个服务承诺和右侧仓库图片。

**版式建议**：

- 桌面端严格采用左 `48%`、右 `52%` 分屏。
- 首屏内容高度建议 `760–820px`，不包含 Header。
- 左侧使用 `#0B2920`，右侧图片完整覆盖，不放入卡片。
- 左侧文案垂直居中，H1 控制在约 4–5 行以内。
- 主按钮使用 `#42B978`，次按钮使用深色背景上的描边样式。
- 三项承诺位于按钮下方，通过细分隔线与正文区分。

**素材方向**：

- 使用真实仓库收货、扫码或装箱场景。
- 人物动作与业务明确，画面中应能看到产品、纸箱、扫描设备或工作台。
- 右侧人物主体不要被导航、按钮或浏览器裁切遮挡。

**动效建议**：

- 页面加载时仅允许文案轻微淡入和图片低幅缩放，时长 `400–600ms`。
- CTA Hover 可使用背景色切换和箭头平移 `2–4px`。
- 禁止漂浮徽章、无限发光和大范围视差。

### 6.3 平台与经营数据

**保留内容**：平台文案、六个平台名称、四项经营数据。

**版式建议**：

- 白色背景，模块高度紧凑。
- 第一行展示平台 Logo 或品牌名称，使用一致的视觉高度。
- 第二行展示 `6+ / 30+ / 3 / 1-on-1`，用细分隔线组织，不做四张大卡片。
- 平台 Logo 可保留各自品牌色，但整体饱和度应受控。

**交互建议**：

- 平台滚动速度放慢，完整循环建议不少于 `28–36s`。
- 鼠标悬停时暂停滚动。
- 用户开启减少动态效果时，改为静态展示。
- 移动端可使用可滑动横向列表，但应显示下一项的局部提示。

### 6.4 三项核心优势

**保留内容**：标题、三项优势文案、Why JW Dropshipping 链接。

**版式建议**：

- 使用三列均分布局，区块背景建议白色。
- 每列使用一个简洁图标、标题和短说明。
- 三列之间使用细竖线或足够留白，不使用独立浮动卡片。
- 图标控制在 `28–34px`，使用 `#167449`。
- 底部文本链接应明显但克制，带箭头反馈。

**动效建议**：

- 滚动进入时按列轻微错峰出现，间隔不超过 `80ms`。
- Hover 只改变图标和链接状态，不整体大幅上浮。

### 6.5 五步合作流程

**保留内容**：五个步骤及现有文案。

**版式建议**：

- 桌面端横向五步，固定展示，不自动轮播。
- 每步包含编号、图标、标题和一句说明。
- 使用连续基线、分隔线或递进编号表达流程关系。
- 当前页面阅读重点应是“合作并不复杂”，避免添加过多说明。
- 背景可使用 `#F3F7F4`，与白色上下模块形成节奏变化。

**移动端**：

- 改为纵向时间线。
- 编号与连接线固定在左侧，正文位于右侧。
- 每一步之间保持 `28–36px` 间距。

**动效建议**：

- 滚动时连接线可按阅读进度轻微填充。
- 不允许自动切换步骤或隐藏未激活内容。

### 6.6 六项核心服务

**保留内容**：六项服务、适合对象、三项能力点和 Compare All Services。

**版式建议**：

- 桌面端两行三列。
- 每张卡片整卡可点击。
- 图片比例固定 `4:3`，卡片圆角 `6–8px`。
- 图片下依次为服务标题、适合对象、三项能力、Explore Service。
- 卡片之间依靠边框和留白区分，不使用厚重阴影。
- 标题区域与卡片网格保持明显层级。
- `Compare All Services` 作为网格底部统一 CTA。

**素材方向**：

- Product Sourcing：产品比较、样品、供应商资料。
- Quality Control：检查产品、尺寸、数量或外观。
- Private Label & Packaging：标签、盒、插页和品牌包材。
- Dropshipping Fulfillment：单件订单拣货与包装。
- China 3PL Fulfillment：货架、库存与多 SKU 管理。
- Order Automation：扫码、订单屏幕或打单过程。

**交互建议**：

- Hover 时边框变为主绿色，图片缩放不超过 `1.025`。
- 箭头轻微右移，卡片整体位移不超过 `3px`。
- 移动端单列，图片和文字不得被固定高度裁切。

### 6.7 对比区域

**保留内容**：Typical sourcing agent 与 JW Dropshipping 的五组对比。

**版式建议**：

- 使用全宽双栏结构，不做两张悬浮大卡片。
- 左侧使用浅灰，右侧使用浅绿色。
- 每一行为直接对应关系，保证视觉对齐。
- 左侧可使用低对比度减号或关闭图标，右侧使用绿色勾选。
- JW 一侧的文字字重略高，但避免强烈促销感。

**移动端**：

- 优先保留左右对应关系，可采用每组上下排列。
- 不建议让整张表产生页面级横向滚动。

### 6.8 QC 与仓库能力证明

**保留内容**：三张 QC 图片、检查项目、QC 报告示意和 CTA。

**版式建议**：

- 桌面端左右分栏，图片约占 `52%`，内容约占 `48%`。
- 图片区使用一张大图和两张细节图，采用紧密拼接而非装饰性图片墙。
- 右侧标题、检查清单和报告示意形成清晰纵向层级。
- 报告 UI 应像真实运营界面：精确、紧凑、可扫描。
- `Waiting for approval` 使用警示但克制的状态色，不能破坏品牌配色。

**素材方向**：

- 主图展示人员正在执行检查。
- 细节图展示尺寸、条码、包装、外观或记录动作。
- 避免只拍整齐摆放的产品而没有检查动作。

**动效建议**：

- 报告数据可在进入视口时依次出现，但不使用数字快速滚动。
- 图片 Hover 可显示简短说明，不覆盖主要业务细节。

### 6.9 客户反馈

**保留内容**：三条评价、五星、姓名、国家、服务标签和更多故事链接。

**版式建议**：

- 使用一条重点评价加两条普通评价。
- 重点评价占更大宽度或两列空间。
- 评价内容保持 2–4 行主要阅读长度。
- 姓名、国家和服务标签靠近评价底部，信息结构统一。
- 星级使用品牌绿或克制金色，不使用夸张发光效果。
- 不添加评价自动轮播。

**交互建议**：

- Hover 仅提升边框对比度。
- `Read More Seller Stories` 使用清晰文本链接。
- 移动端按重点评价、普通评价顺序纵向排列。

### 6.10 FAQ

**保留内容**：现有五个问题及答案。

**版式建议**：

- 左侧固定标题与说明，右侧使用 Accordion。
- 默认只展开第一项，同时最多展开一个问题。
- 使用细分隔线，不将每个问题设计成独立卡片。
- 展开图标使用加号，展开后旋转为关闭状态。

**交互建议**：

- 展开收起时长建议 `180–240ms`。
- 动画应包含内容高度与透明度过渡。
- 保证键盘和屏幕阅读器可操作。
- 移动端标题位于 Accordion 上方，不使用 Sticky。

### 6.11 最终报价区域

**保留内容**：现有标题、说明、全部字段、六项多选和提交按钮。

**版式建议**：

- 使用 `#0B2920` 全宽背景。
- 桌面端左侧文案约 `40–44%`，右侧表单约 `56–60%`。
- 左侧可补充真实客户经理或仓库沟通照片，但不能挤压主文案。
- 表单使用白色或非常浅的绿色背景，圆角不超过 `8px`。
- 输入框高度建议 `50–54px`，标签始终显示。
- 六项需求使用可多选选项，不使用下拉菜单。
- 主按钮占满表单有效宽度，使用 `#42B978`。

**表单交互**：

- Focus 状态使用主绿色边框与低透明度外环。
- 多选项必须有明确选中状态和勾选图标。
- 必填错误应显示字段级文字，不只改变边框颜色。
- 提交中显示 Loading 状态并禁用重复提交。
- 成功后进入现有 Thank You 页面。
- 不在输入过程中触发不必要弹窗。

**移动端**：

- 文案在上、表单在下。
- 所有双列字段改为单列。
- 输入控件字体不得小于 `16px`，避免移动浏览器自动缩放。
- 多选项可单列展示，保证点击区域高度不少于 `44px`。

### 6.12 Footer

**保留内容**：Logo、品牌说明、服务链接、公司链接、报价入口、版权信息。

**版式建议**：

- 深绿色或接近深绿色背景，与报价区域形成连续但可区分的收尾。
- 桌面端使用品牌信息加三列导航。
- 链接行高和间距适合快速扫描。
- 不添加复杂社交图标或无业务价值的认证徽章。
- 移动端使用自然纵向排列，不强制全部折叠。

## 7. 动效与交互总规范

### 7.1 动效原则

- 动效服务于层级、反馈和流程理解，不作为装饰主体。
- 默认过渡时长 `160–280ms`。
- 首次滚动出现可使用 `400–600ms`，位移不超过 `16px`。
- 同组元素错峰间隔不超过 `80ms`。
- 不使用弹跳、连续漂浮、大幅旋转和过度视差。

### 7.2 建议交互

- 按钮：背景颜色切换，箭头轻移。
- 服务卡片：边框增强、图片轻微缩放。
- 平台 Logo：慢速滚动，Hover 暂停。
- 流程：滚动时连接线渐进填充。
- FAQ：单项展开和高度过渡。
- 表单：Focus、选中、错误、提交中和成功状态完整。
- Header：吸顶后轻微压缩，但不改变主要导航位置。

### 7.3 减少动态效果

当系统启用 `prefers-reduced-motion: reduce` 时：

- 停止平台自动滚动。
- 禁用图片缩放和滚动进入位移。
- FAQ 和菜单使用即时或极短过渡。
- 保留必要的状态反馈。

## 8. 响应式适配要求

### 8.1 建议设计尺寸

- 宽屏桌面：`1440px`
- 标准桌面：`1280px`
- 平板横向：`1024px`
- 平板竖向：`768px`
- 移动端：`390px`
- 小屏移动端：`360px`

### 8.2 桌面端要求

- 保持完整导航和 12 列栅格。
- Hero 分屏比例稳定，图片不被放入卡片。
- 服务保持三列，对比保持双栏，流程保持五列。
- 文本宽度受控，避免大屏出现过长行。
- 1440px 以上不继续放大字号，扩大外侧留白即可。

### 8.3 平板端要求

- Header 可进入紧凑导航或移动菜单。
- 服务卡片由三列调整为两列。
- 流程可保持横向滚动或进入纵向时间线，优先保证完整阅读。
- QC、FAQ 和报价区可调整为单列。
- 不允许文字和图片出现重叠。

### 8.4 移动端要求

- Hero 改为文案在上、图片在下。
- H1 建议 `38–44px`，不得按视口宽度连续缩放。
- 主次按钮可纵向排列并保持一致宽度。
- 数据区使用两列或横向可滑动布局。
- 三项优势、服务、评价全部改为单列。
- 五步流程改为纵向时间线。
- 对比内容按对应组上下排列。
- QC 图片先展示主图，再展示细节图与报告。
- FAQ 标题不 Sticky。
- 报价表单全部单列。
- 页面不得产生整体横向滚动。
- 所有按钮和可点击区域最小高度 `44px`。

## 9. 可访问性与性能要求

### 9.1 可访问性

- 正文与背景对比度满足 WCAG AA。
- 所有功能图片提供准确 Alt 文本；装饰图片使用空 Alt。
- 不通过颜色单独表达选中、成功或错误状态。
- 键盘可访问导航、下拉菜单、FAQ、表单和按钮。
- Focus 样式必须可见。
- 表单标签不可只使用 Placeholder 替代。
- 视频提供字幕或文字内容摘要。

### 9.2 性能

- 首屏主图提供桌面和移动端响应式尺寸。
- 首屏图片优先加载，其他图片 Lazy Load。
- 图片优先使用 AVIF/WebP。
- 视频默认不自动播放声音，不预加载完整文件。
- 避免同时加载多个高分辨率背景视频。
- 动效优先使用 `transform` 和 `opacity`。
- 不引入仅用于单一小效果的大型动画库。

## 10. UI 状态设计清单

设计稿必须覆盖：

- Header 默认、吸顶、Services 展开、移动菜单展开
- 主次按钮默认、Hover、Focus、Disabled
- 服务卡片默认和 Hover
- 平台滚动和暂停状态
- FAQ 收起和展开状态
- 表单输入默认、Focus、已填写、错误、Disabled
- 多选项默认和选中状态
- 表单提交中、提交成功和提交失败状态
- 图片或视频加载失败的合理占位状态
- 移动端导航、流程、对比和报价表单

## 11. 设计交付物

UI 设计师需交付：

1. 1440px 完整 Home 高保真设计稿
2. 390px 完整 Home 高保真设计稿
3. 1024px 或 768px 关键响应式页面稿
4. Header、按钮、表单、Accordion、服务卡片组件规范
5. 色彩、字体、间距、边框和图标规范
6. Hover、展开、滚动和表单反馈交互说明
7. 图片和视频素材清单及裁切建议
8. 所有导出素材的 1x/2x 或响应式版本
9. 动效时长、缓动和触发条件标注
10. 开发交付说明，包括断点和特殊布局规则

## 12. 验收标准

设计方案满足以下条件方可进入开发：

- 未改变现有模块顺序、文案和业务逻辑。
- 三个品牌绿色值使用准确。
- 首屏能够在 5 秒内让用户理解 JW 的业务。
- 报价 CTA 在页面首屏和末屏均清晰可见。
- 页面没有明显模板感、玻璃拟态和过量渐变。
- 主要视觉素材能够证明真实供应链能力。
- 服务、流程、QC、评价和 FAQ 均可快速扫描。
- 桌面端和移动端不存在文字、图片和控件重叠。
- 360px 宽度下不存在页面级横向滚动。
- 表单状态、键盘操作和减少动态效果均有设计说明。
- 设计组件能够被前端稳定实现，不依赖不可控的视觉特效。

## 13. 最终体验描述

最终 Home 页面应具备以下体验：

- 首屏像成熟供应链服务商一样直接、可信。
- 页面阅读节奏完整，但没有冗余营销信息。
- 真实仓库、团队和 QC 素材成为信任核心。
- 绿色品牌体系明确，但页面不被单一绿色淹没。
- 用户能够自然完成“理解业务 → 判断流程 → 比较差异 → 查看证据 → 获取报价”的决策路径。
- 整体质感应接近成熟国际 B2B 服务品牌，而不是普通 dropshipping 模板网站。
